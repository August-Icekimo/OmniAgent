思考模式：閱讀程式碼、討論設計，**不實作任何變更**。

## 用途

在開始提案或實作前，先徹底理解現有程式碼的結構、行為與限制。
適合用於：「這段邏輯怎麼運作？」「改這裡會影響哪些地方？」「有什麼現有機制可以重用？」

## 步驟

1. **釐清探索範圍**

   若使用者提供了 `$ARGUMENTS`，以此為起點。
   否則請使用者描述想探索的問題或模組。

2. **閱讀相關程式碼**

   - 從 `CLAUDE.md` 的 Key File Locations 找起點
   - 追蹤 import、呼叫鏈、資料流
   - 閱讀 config 檔案（`routing_config.json`、`SOUL.md` 等）
   - 若涉及 DB，閱讀 `db/SCHEMA.md`

3. **整理發現**

   以下列格式回報：
   - **現在的做法**：現有邏輯的簡要描述
   - **關鍵檔案**：路徑 + 關鍵行號
   - **隱含限制**：哪些假設或依賴關係需要注意
   - **開放問題**：哪些地方還不清楚，需要使用者確認

4. **不實作**

   本指令嚴格限於閱讀與討論。
   若使用者要求實作，提示他們改用 `/opsx-apply`。
