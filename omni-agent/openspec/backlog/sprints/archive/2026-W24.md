### What worked
- 唯一 committed 項目如期完成並 merge（PR #9）。三個 Goal 全達標。
- 設計階段就抓到 backlog 的錯誤假設（「既有 Google OAuth gateway 層」其實不存在，真正的門禁在獨立的 secure-gateway/Caddy），及早改設計避免白工。
- 實機驗證（podman compose 全鏈路 + headless chromium 截圖）抓到三個只有跑起來才看得到的 bug：共享 volume 非 root 寫入權限、聊天貼原始輸出、歷史汙染導致模型仿造假連結。

### What didn't
- local gemma planner 不穩：模糊指令（如「whoami 看看」「cal 1979」）會直接幻覺輸出、不真的路由到 terminal 技能（`cal` 根本沒裝也照編月曆）。功能本身沒問題，但使用體驗受 planner 品質拖累。
- viewer 連結進對話歷史造成「學舌仿造假連結」，補了 strip + 清庫才壓下；提醒日後任何「會出現在回覆裡的結構化字串」都要評估是否入庫。

### Carry-over
- **planner 幻覺（部分解決）**：sprint 外追加的 native tool calling 重構（PR #10 merged）已**消除危險的偽造**——工具輸出由 harness 注入、模型無法再編造命令輸出/假連結（spike + 實機驗證）。**但完整解決待另一次重構**：殘留「模糊口語時 local 模型聊天而非呼叫工具、且會學舌歷史」的 intent gap（危害低，不偽造輸出）。下一步方向：強化工具路由/意圖辨識，可能也用某種 tool 機制（使用者構想），或 sanitize 入庫的學舌文字（目前只 strip 連結）。
- **Claude/Gemini tool 路徑**（PR #10）無 API key 未實機驗證，為 fallback；正式倚賴前補 smoke test。確認 resume 跨回合 e2e 僅 unit 驗。
- secure-gateway 的 Caddy `/terminal*`（admin_policy + WS 升級）路由為外部相依——使用者回報已處理（待最終對外鏈路實測）。

### Additional delivered（sprint 外追加，2026-06-20）
- **`auto-confirm-upgrade-cleanup`（commit ebbf9e7 + 歸檔）**：全拆壞掉的 stress-escalation
  升級鏈路。原 idea 標的函式 `auto_confirm_model_upgrade` 已在 PR #10 消失；探索後發現殘留的
  「壓力→提案→確認→升級模型」在 live path 端到端壞掉（確認端只在 gateway 不再呼叫的 `/chat`、
  `router` 無 `set_default`、確認後只對 admin 謊報）。經確認採 (B) 全拆，**保留 stress 情緒感知
  （stress_logs 寫入/SOUL context）**、只拆升級反應。
- **`forwarder-delivery-failure-handling`（commit d5ac362 + 歸檔，P1）**：投遞失敗不再靜默丟失。
  原本失敗只 log、turn 照標 delivered/done → brain 答案永久丟失。改為成功才標 done；失敗依分類
  退避重試（指數 base 5s 上限 300s、上限 5 次）、`next_delivery_at` 閘門防 head-of-line blocking、
  耗盡/終局 → `undeliverable` dead-letter 保留 result、併入每日 admin 摘要。**runtime e2e 實跑通過**。
- **實測教訓（值得記）**：
  - **bug 會隨重構搬家**：此 idea 的 Links 指 `brain.go processNextMessage`（conversational-turn-assembly
    PR #11 後已不存在），真正的靜默丟失已遷到 `turns.go deliverDoneTurn`。歸檔的 idea Links 跨重構
    會 stale，動手前務必先核對現況位置。
  - **migration 仍需手動套用**（重申上一段教訓）：010 一樣得手動 `psql < 010_*.sql`，fresh volume 才自動跑。
  - **runtime e2e 取得「確定性失敗」的手段**：真實 send 路徑難強迫 5xx，採 **sentinel-scoped、env-gated
    的注入 hook**（只對測試 user 失敗、不影響真實流量），跑完即移除並重建乾淨 binary——可確定性驗退避
    迴圈 1→5 + undeliverable。terminal(400) 路徑則用真實 Telegram bogus chat 即可（不需 hook）。
  - **`git mv` 歸檔陷阱**：先改檔再 `git mv` 卻沒先 `git add`，編輯會被「100% rename」commit 漏掉
    （auto-confirm 歸檔踩到，補了一個 commit 修）。**正確流程：先 `git add` 編輯，再 `git mv`。**
