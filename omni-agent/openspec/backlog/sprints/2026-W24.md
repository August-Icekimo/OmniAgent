### What worked
- 唯一 committed 項目如期完成並 merge（PR #9）。三個 Goal 全達標。
- 設計階段就抓到 backlog 的錯誤假設（「既有 Google OAuth gateway 層」其實不存在，真正的門禁在獨立的 secure-gateway/Caddy），及早改設計避免白工。
- 實機驗證（podman compose 全鏈路 + headless chromium 截圖）抓到三個只有跑起來才看得到的 bug：共享 volume 非 root 寫入權限、聊天貼原始輸出、歷史汙染導致模型仿造假連結。

### What didn't
- local gemma planner 不穩：模糊指令（如「whoami 看看」「cal 1979」）會直接幻覺輸出、不真的路由到 terminal 技能（`cal` 根本沒裝也照編月曆）。功能本身沒問題，但使用體驗受 planner 品質拖累。
- viewer 連結進對話歷史造成「學舌仿造假連結」，補了 strip + 清庫才壓下；提醒日後任何「會出現在回覆裡的結構化字串」都要評估是否入庫。

### Carry-over
- **planner 幻覺（部分解決）**：sprint 外追加的 native tool calling 重構（PR #10 merged）已**消除危險的偽造**——工具輸出由 harness 注入、模型無法再編造命令輸出/假連結（spike + 實機驗證）。**但完整解決待另一次重構**：殘留「模糊口語時 local 模型聊天而非呼叫工具、且會學舌歷史」的 intent gap（危害低，不偽造輸出）。下一步方向：強化工具路由/意圖辨識，可能也用某種 tool 機制（使用者構想），或 sanitize 入庫的學舌文字（目前只 strip 連結）。
- **Claude/Gemini tool 路徑**（PR #10）無 API key 未實機驗證，為 fallback；正式倚賴前補 smoke test。確認 resume 跨回合 e2e 僅 unit 驗。
- secure-gateway 的 Caddy `/terminal*`（admin_policy + WS 升級）路由為外部相依——使用者回報已處理（待最終對外鏈路實測）。
